## D86 — Multi-agent guidance: one coordinator, parallel helpers, shared ledger (2026-10-10)

- **Owner request:** keep the rolling, screen-aware intelligence of D84, but make it fast, and make the choice cards smart instead of constant. The owner approved multiple agents; intelligence is the priority.
- **Choice:** ChalkCore `GuideCoordinator` (pure, headless) coordinates bounded, stateless helpers that all read one `GuideLedger`.
  - **Planner** (Sonnet): the next single action.
  - **Scout** (Sonnet, background): predicts the next step while the user acts.
  - **Checker** (Haiku): step done, prediction right, goal reached, which option.
  - **Fixer** (Opus): only when stuck.
  - Chalk coordinates them; no agent calls another; SDK spawn/teams stay off.
- **Why stateless instead of the D84 persistent session:**
  - On the dev profile, a `complete` call reached first text in 2.7 s, against 3.4 s for a session start and 2.9 s for a follow-up send (p50, 3 runs each).
  - Parallel helpers can't share one session anyway.
  - The ledger carries the shared memory (goal, fixed task date, verified outcomes, choices, notes).
- **Latency:**
  - A prediction matching the new screen shows with no model call; a plausible one races checker against planner; a scout still thinking races a fresh plan.
  - The planner's one-line reply is used as soon as it parses.
  - One settled look replaces two readings.
  - The first step reuses the key-down screenshot.
  - The scout can predict that the current step finishes the task, which skips planning.
- **Done detection:**
  - The predicate is read on the tree.
  - A click on the circle that makes the app react counts as done.
  - Typing finishes on Return, Tab, focus leaving the field, or 2.5 s idle.
  - The checker is used only when the app can't tell; if it fails, a click on the circle is trusted.
  - Predicates match whole words.
  - A predicate that only names the clicked control is dropped; a text predicate on a typing step becomes value_contains.
- **Cards:**
  - "Screen changed" and "couldn't establish" cards are removed: a silent re-plan, then the fixer, then a card only if still stuck.
  - Consequential actions get a spoken heads-up, not a confirmation card, because Chalk never clicks: the user's own click confirms.
  - Planner questions remain for real ambiguity. Spoken answers are matched exactly, then by the checker; an unmatched answer becomes the user's direction.
  - The checker may tell the user why a step isn't done.
- **Removed:** `AdaptiveAgentTeam`, `AdaptiveWorkflow`, `StepOutcomeTracker`, `RollingGuidePlan` and the `adaptive_guide` rule overrides. `AdaptiveDecision` was kept for the card.
- **Testing:**
  - New use-case simulator, `Eval/guide-sim`. Scripted screens (`Eval/usecases`) and a simulated user that follows the circle and deviates as scripted, with real calls through the compiled engine. It never launches the app.
  - Dev profile: 7/7 scenarios reach the goal, 0 wrong circles.
  - Claude timings need a `--profile demo` run with the owner's OK.
